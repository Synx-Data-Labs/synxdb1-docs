About SynxDB R

The SynxDB R Client (SynxDBR) is an interactive in-database data analytics tool for SynxDB. The client provides an R interface to tables and views, and requires no SQL knowledge to operate on these database objects.

You can use SynxDBR with the SynxDB PL/R procedural language to run an R function on data stored in SynxDB. SynxDBR parses the R function and creates a user-defined function (UDF) for execution in SynxDB. SynxDB runs the UDF in parallel on the segment hosts.

You can similarly use SynxDBR with SynxDB PL/Container 3 (Beta), to run an R function against SynxDB data in a high-performance R sandbox runtime environment.

No analytic data is loaded into R when you use SynxDBR, a key requirement when dealing with large data sets. Only the R function and minimal data is transferred between R and SynxDB.

Prerequisites

You can use SynxDBR with SynxDB and the PL/R and PL/Container procedural languages. Before you install and run SynxDBR on a client system:

  • Ensure that your SynxDB installation is running version 6.1 or newer.

  • Ensure that your client development system has connectivity to the SynxDB master host.

  • Ensure that R version 3.6.0 or newer is installed on your client system, and that you set the $R_HOME environment variable appropriately.

  • Determine the procedural language(s) you plan to use with SynxDBR, and ensure that the language(s) is installed and configured in your SynxDB cluster. Refer to PL/R Language and PL/Container Language (3.0 Beta) for language installation and configuration instructions.

  • Verify that you have registered the procedural language(s) in each database in which you plan to use SynxDBR to read data from or write data to SynxDB. For example, the following command lists the extensions and languages registered in the database named testdb:

    $ psql -h gpmaster -d testdb -c '\dx'
                                     List of installed extensions
    Name     | Version  |   Schema   |                          Description     
                      
-------------+----------+------------+----------------------------------------------------------------
 plcontainer | 1.0.0    | public     | GPDB execution sandboxing for Python and R
 plpgsql     | 1.0      | pg_catalog | PL/pgSQL procedural language
 plr         | 8.3.0.16 | public     | load R interpreter and run R script from within a database

    Check for the plr and/or plcontainer extension Name.

Installing the SynxDB R Client

SynxDBR is an R package. You can obtain the package from the SynxDBR github repository and install the package within the R console.

  1. Download the package from the SynxDBR github repository. The naming format of the downloaded file is greenplumR‑<version>‑gp6.tar.gz.

    Note the file system location of the downloaded file.

  2. Follow the instructions in Verifying the SynxDB Software Download to verify the integrity of the SynxDB Procedural Languages SynxDBR software.

  3. Install the dependent R packages: ini, shiny, and RPostgreSQL. For example, enter the R console and run the following, or equivalent, command:

    user@clientsys$ R
> install.packages(c("ini", "shiny", "RPostgreSQL"))

    You may be prompted to select a CRAN download mirror. And, depending on your client system configuration, you may be prompted to use or create a personal library.

    After downloading, R builds and installs these and dependent packages.

  4. Install the SynxDBR R package:

    > install.packages("/path/to/greenplumR‑<version>‑gp6.tar.gz", repos = NULL, type = "source")

  5. Install the Rdpack documentation package:

    > install.packages("Rdpack")

Using the SynxDB R Client

You use SynxDBR to perform in-database analytics. Typical operations that you may perform include:

  • Loading the SynxDBR package.
  • Connecting to and disconnecting from SynxDB.
  • Examining database objects.
  • Analyzing and manipulating data.
  • Running R functions in SynxDB.

Loading SynxDBR

Use the R library() function to load SynxDBR:

user@clientsys$ R
> library("SynxDBR")

Connecting to SynxDB

The db.connect() and db.connect.dsn() SynxDBR functions establish a connection to SynxDB. The db.disconnect() function closes a database connection.

The SynxDBR connect and disconnect function signatures follow:

db.connect( host = "localhost", user = Sys.getenv("USER"),
            dbname = user, password = "", port = 5432, conn.pkg = "RPostgreSQL",
            default.schemas = NULL, verbose = TRUE, quick = FALSE )

db.connect.dsn( dsn.key, db.ini = "~/db.ini", default.schemas = NULL,
                verbose = TRUE, quick = FALSE )

db.disconnect( conn.id = 1, verbose = TRUE, force = FALSE )

When you connect to SynxDB, you provide the master host, port, database name, user name, password, and other information via function arguments or a data source name (DSN) file. If you do not specify an argument or value, SynxDBR uses the default.

The db.connect[.dsn]() functions return an integer connection identifier. You specify this identifier when you operate on tables or views in the database. You also specify this identifier when you close the connection.

The db.disconnect() function returns a logical that identifies whether or not the connection was successfully disconnected.

To list and display information about active SynxDB connections, use the db.list() function.

Example:

## connect to SynxDB named testdb on host gpmaster
> cid_to_testdb <- db.connect( host = "gpmaster", port=5432, dbname = "testdb" )
Loading required package: DBI
Created a connection to database with ID 1 
[1] 1

> db.list()
Database Connection Info
## -------------------------------
[Connection ID 1]
Host     :    gpmaster
User     :    gpadmin
Database :    testdb
DBMS     :    SynxDB 1

> db.disconnect( cid_to_testdb )
Connection 1 is disconnected!
[1] TRUE

Examining Database Obects

The db.objects() function lists the tables and views in the database identified by a specific connection identifier. The function signature is:

db.objects( search = NULL, conn.id = 1 )

If you choose, you can specify a filter string to narrow the returned results. For example, to list the tables and views in the public schema in the database identified by the default connection identifier, invoke the function as follows:

> db.objects( search = "public." )

Analyzing and Manipulating Data

The fundamental data structure of R is the data.frame. A data frame is a collection of variables represented as a list of vectors. SynxDBR operates on db.data.frame objects, and exposes functions to convert to and manipulate objects of this type:

  • as.db.data.frame() - writes data in a file or a data.frame into a SynxDB table. You can also use the function to write the results of a query into a table, or to create a local db.data.frame.
  • db.data.frame() - creates a temporary R object that references a view or table in a SynxDB. No data is loaded into R when you use this function.

Example:

## create a db.data.frame from the abalone example data set;
## abalone is a data.frame
> abdf1 <- as.db.data.frame(abalone, conn.id = cid_to_testdb, verbose = FALSE)

Running R Functions in SynxDB

SynxDBR supports two functions that allow you to run an R function, in-database, on every row of a SynxDB table: db.gpapply() and db.gptapply(). You can use the SynxDB PL/R or PL/Container procedural language as the vehicle in which to run the function.

The function signatures follow:

db.gpapply( X, MARGIN = NULL, FUN = NULL, output.name = NULL, output.signature = NULL,
            clear.existing = FALSE, case.sensitive = FALSE, output.distributeOn = NULL,
            debugger.mode = FALSE, runtime.id = "plc_r_shared", language = "plcontainer",
            input.signature = NULL, ... )

db.gptapply( X, INDEX, FUN = NULL, output.name = NULL, output.signature = NULL,
             clear.existing = FALSE, case.sensitive = FALSE,
             output.distributeOn = NULL, debugger.mode = FALSE,
             runtime.id = "plc_r_shared", language = "plcontainer",
             input.signature = NULL, ... )

Use the second variant of the function when the table data is indexed.

By default, db.gp[t]apply() passes a single data frame input argument to the R function FUN. If you define FUN to take a list of arguments, you must specify the function argument name to SynxDB table column name mapping in input.signature. You must specify this mapping in table column order.

Example 1:

Create a SynxDB table named table1 in the database named testdb. This table has a single integer-type field. Populate the table with some data:

user@clientsys$ psql -h gpmaster -d testdb
testdb=# CREATE TABLE table1( id int );
testdb=# INSERT INTO table1 SELECT generate_series(1,13);
testdb=# \q

Create an R function that increments an integer. Run the function on table1 in SynxDB using the PL/R procedural language. Then write the new values to a table named table1_r_inc:

user@clientsys$ R
> ## create a reference to table1
> t1 <- db.data.frame("public.table1")

> ## create an R function that increment an integer by 1
> fn.function_plus_one <- function(num)
{
    return (num[[1]] + 1)
}

> ## create the function output signature
> .sig <- list( "num" = "int" )

> ## run the function in SynxDB and print
> x <- db.gpapply( t1, output.name = NULL, FUN = fn.function_plus_one,
  output.signature = .sig, clear.existing = TRUE, case.sensitive = TRUE, language = "plr" )
> print(x)
   num
1    2
2    6
3   12
4   13
5    3
6    4
7    5
8    7
9    8
10   9
11  10
12  11
13  14

> ## run the function in SynxDB and write to the output table
> db.gpapply(t1, output.name = "public.table1_r_inc", FUN = fn.function_plus_one,
   output.signature = .sig, clear.existing = TRUE, case.sensitive = TRUE,
   language = "plr" )

## list database objects, should display the newly created table
> db.objects( search = "public.")
[1] "public.abalone_from_r"		"public.table1_r_inc"

Example 2:

Create a SynxDB table named table2 in the database named testdb. This table has two integer-type fields. Populate the table with some data:

user@clientsys$ psql -h gpmaster -d testdb
testdb=# CREATE TABLE table2( c1 int, c2 int );
testdb=# INSERT INTO table2 VALUES (1, 2);
testdb=#\q

Create an R function that takes two integer arguments, manipulates the arguments, and returns both. Run the function on the data in table2 in SynxDB using the PL/R procedural language, writing the new values to a table named table2_r_upd:

user@clientsys$ R
> ## create a reference to table2
> t2 <- db.data.frame("public.table2")

> ## create the R function
> fn.func_with_two_args <- function(a, b)
{
    a <- a * 20
    b <- a + 66
    c <- list(a, b)
    return (as.data.frame(c))
}

> ## create the function input signature, mapping function argument name to
> ## table column name
> input.sig <- list('a' = 'c1', 'b' = 'c2')

> ## create the function output signature
> return.sig <- list('a' = 'int', 'b' = 'int')

> ## run the function in SynxDB and write to the output table
> db.gpapply(t2, output.name = "public.table2_r_upd", FUN = fn.func_with_two_args,
   output.signature = return.sig, clear.existing = TRUE, case.sensitive = TRUE,
   language = "plr", input.signature = input.sig )

View the contents of the SynxDB table named table2_r_upd:

user@clientsys$ psql -h gpmaster -d testdb
testdb=# SELECT * FROM table2_r_upd;
 a  | b  
----+----
 20 | 86
(1 row)
testdb=# \q

Limitations

SynxDBR has the following limitations:

  • The db.gpapply() and db.gptapply() functions currently operate only on conn.id = 1.
  • The SynxDBR function reference pages are not yet published. You can find html versions of the reference pages in your R library R/<platform>-library/3.6/SynxDBR/html directory. Open the 00Index.html file in the browser of your choice and select the function of interest.
  • The SynxDBR() graphical user interface is currently unsupported.
