SynxDB 2: Pre-Migration Guide

Purpose

This guide helps you identify and address Greenplum 6 proprietary features before migration to SynxDB 2.

Security Considerations

SynxDB maintains high security standards through:

  • Cryptographically signed RPM packages
  • Signed repository metadata
  • GPG key verification
  • Package signature validation at multiple stages

All artifacts used in this process are cryptographically signed to ensure:

  • Package integrity
  • Origin authenticity
  • Protection against tampering
  • Secure dependency management

Configuration Safety

Before making any configuration changes:

  • Backup postgresql.conf files from all segment data directories
  • Document existing configurations
  • Test changes in a development environment first

Repository Access

While this guide focuses on identifying proprietary features, note that subsequent migration steps will require repository access. Synx Data Labs can provide a complete repository mirror for hosting within your environment if:

  • Your hosts don’t have external internet access
  • You prefer to host repositories within your infrastructure
  • You need to ensure package consistency across deployments

Contact Synx Data Labs before beginning migration steps to ensure proper repository access is in place for your environment.

Proprietary Features to Identify

1. Greenplum Command Center (GPCC)

The Greenplum Command Center is a Broadcom proprietary offering not available in SynxDB. The primary concern during migration is the metrics_collector shared library. This configuration must be addressed before the SynxDB drop-in-replacement process, as the cluster will fail to start if metrics_collector remains in shared_preload_libraries (the library is not available in SynxDB).

Detection

Check if metrics_collector is configured in shared_preload_libraries:

gpconfig -s shared_preload_libraries

Remediation

⚠️ Important: Before making any changes, backup postgresql.conf files from all segment data directories.

Based on your configuration:

  1. If metrics_collector is the only entry:
gpconfig -r shared_preload_libraries
  1. If metrics_collector is part of a comma-separated list:
gpconfig -c shared_preload_libraries -v "comma,separated,list"

Replace “comma,separated,list” with your desired remaining libraries.

After updating the configuration:

  1. Restart the Greenplum cluster for changes to take effect
  2. Verify the configuration change:
gpconfig -s shared_preload_libraries

Ensure metrics_collector is no longer present in the output.

2. QuickLZ Compression

The QuickLZ compression algorithm is proprietary to Broadcom and not available in SynxDB. Before planning any migration, it’s essential to identify if and where QuickLZ compression is being used in your environment.

Detection

Run the following script as gpadmin to identify QuickLZ usage across all databases:

#!/bin/bash
echo "Checking if QuickLZ is in use across all databases..."

for db in $(psql -t -A -c "SELECT datname FROM pg_database WHERE datistemplate = false;"); do
  quicklz_count=$(psql -d $db -X -A -t -c "
    SELECT COUNT(*)
    FROM pg_attribute_encoding, LATERAL unnest(attoptions) AS opt
    WHERE opt = 'compresstype=quicklz';
  ")
  
  if [ "$quicklz_count" -gt 0 ]; then
    echo "QuickLZ is in use in database: $db ($quicklz_count columns)"
  else
    echo "QuickLZ is NOT in use in database: $db"
  fi
done

This script will check each non-template database and report whether QuickLZ compression is in use, along with the number of affected columns.

Impact

The presence of QuickLZ compression requires careful consideration in migration planning, as it is not supported in SynxDB. If QuickLZ is detected, further analysis and planning will be needed before proceeding with migration.

Pre-migration Assessment Checklist

  1. GPCC Check:

    • Check for GPCC metrics_collector in shared_preload_libraries
    • Document current monitoring setup for future reference

  2. QuickLZ Check:

    • Run QuickLZ detection script across all databases
    • Document any instances of QuickLZ usage for further analysis

Additional Considerations

  • Test changes in a development environment first
  • Document current configurations for reference
