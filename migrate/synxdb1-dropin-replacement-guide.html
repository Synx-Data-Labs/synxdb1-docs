SynxDB 1: Drop-in Replacement Guide

Purpose

This guide walks through the process of replacing a running Greenplum 6 installation with SynxDB 1 while maintaining fallback capability.

Security Considerations

SynxDB maintains high security standards through:

  • Cryptographically signed RPM packages
  • Signed repository metadata
  • GPG key verification
  • Package signature validation at multiple stages

All artifacts used in this process are cryptographically signed to ensure:

  • Package integrity
  • Origin authenticity
  • Protection against tampering
  • Secure dependency management

Package Verification

This guide includes steps to:

  • Import and verify the SynxDB GPG key
  • Verify package signatures before installation
  • Validate repository metadata
  • Confirm successful package installation

Configuration Safety

Before making any configuration changes:

  • Backup postgresql.conf files from all segment data directories
  • Document existing Greenplum configurations
  • Preserve existing Greenplum installation for fallback capability

Repository Access

This guide assumes all cluster hosts have external access to Synx Data Labs repositories. For environments with restricted external access or to ensure consistent package availability, Synx Data Labs can provide a complete repository mirror for hosting within your environment.

Contact Synx Data Labs to obtain repository artifacts for internal hosting if:

  • Your cluster nodes don’t have external internet access
  • You prefer to host repositories within your infrastructure
  • You need to ensure package consistency across deployments

Prerequisites

  • Greenplum 6 cluster running on Enterprise Linux 8 or 9
  • GPCC metrics_collector removed from shared_preload_libraries
  • No QuickLZ compression in use
  • gpadmin user has sudo access across the cluster
  • all_hosts.txt file containing all cluster hostnames

Installation Steps

1. Import SynxDB GPG Key Across Cluster

This step establishes trust for signed SynxDB packages across your cluster:

# Download and verify GPG key
gpssh -f ~/all_hosts.txt -e 'EL_VERSION="el$(rpm --eval '%{rhel}')"; wget -nv https://synxdb-repo.s3.us-west-2.amazonaws.com/${EL_VERSION}/stable/RPM-GPG-KEY-SynxDB'

# Display and inspect the GPG key details
gpssh -f ~/all_hosts.txt -e 'gpg --show-keys RPM-GPG-KEY-SynxDB'

# Import the verified key into the RPM database
gpssh -f ~/all_hosts.txt -e 'sudo rpm --import RPM-GPG-KEY-SynxDB'

# Verify the key was imported correctly
gpssh -f ~/all_hosts.txt -e 'rpm -q gpg-pubkey --qf "%{NAME}-%{VERSION}-%{RELEASE} %{SUMMARY}\n" | grep SynxDB'

2. Install SynxDB Repository

Each package is verified for authenticity and integrity:

# Download release package
gpssh -f ~/all_hosts.txt -e 'EL_VERSION="el$(rpm --eval '%{rhel}')"; wget -nv https://synxdb-repo.s3.us-west-2.amazonaws.com/${EL_VERSION}/noarch/synxdb-release-1.0.0-rc2.${EL_VERSION}.noarch.rpm'

# Verify package signature against imported GPG key
gpssh -f ~/all_hosts.txt -e 'EL_VERSION="el$(rpm --eval '%{rhel}')"; rpm --checksig synxdb-release-1.0.0-rc2.${EL_VERSION}.noarch.rpm'

# Install repository package
gpssh -f ~/all_hosts.txt -e 'EL_VERSION="el$(rpm --eval '%{rhel}')"; sudo dnf install -y synxdb-release-1.0.0-rc2.${EL_VERSION}.noarch.rpm'

# Verify repository installation
gpssh -f ~/all_hosts.txt -e 'sudo dnf repolist'
gpssh -f ~/all_hosts.txt -e 'rpm -qi synxdb-release'

3. Install SynxDB

# Install SynxDB package
gpssh -f ~/all_hosts.txt -e 'sudo dnf install -y synxdb'

# Verify installation
gpssh -f ~/all_hosts.txt -e 'ls -ld /usr/local/synxdb*'
gpssh -f ~/all_hosts.txt -e 'rpm -q synxdb'
gpssh -f ~/all_hosts.txt -e 'rpm -qi synxdb'

4. Verify Current Greenplum Installation

psql -c 'select version()'
which postgres
postgres --version
postgres --gp-version
which psql
psql --version

5. Stop Greenplum Cluster

gpstop -a

6. Configure SynxDB as Drop-in Replacement

# Create symbolic links for drop-in replacement
gpssh -f ~/all_hosts.txt -e 'sudo rm -v /usr/local/greenplum-db'
gpssh -f ~/all_hosts.txt -e 'sudo ln -s /usr/local/synxdb /usr/local/greenplum-db'
gpssh -f ~/all_hosts.txt -e 'sudo ln -s /usr/local/synxdb/synxdb_path.sh /usr/local/synxdb/greenplum_path.sh'

7. Start Cluster with SynxDB

⚠️ IMPORTANT: Start a new gpadmin shell session before proceeding. This ensures:

  • Old environment variables are cleared
  • New environment is configured via /usr/local/greenplum-db/greenplum_path.sh
  • Correct binaries are referenced in PATH
# In your new gpadmin shell:
gpstart -a

# Verify SynxDB is running
psql -c 'select version()'
which postgres
postgres --version
postgres --gp-version
which psql
psql --version

Fallback Procedure

If needed, you can revert to Greenplum 6 using the following steps:

1. Stop Cluster

gpstop -a

2. Restore Greenplum Symbolic Links

# Adjust the version number to match your Greenplum installation
gpssh -f ~/all_hosts.txt -e 'sudo rm -v /usr/local/greenplum-db'
gpssh -f ~/all_hosts.txt -e 'sudo ln -s /usr/local/greenplum-db-6.26.4 /usr/local/greenplum-db'

3. Start Cluster with Greenplum

⚠️ IMPORTANT: Start a new gpadmin shell session before proceeding. This ensures:

  • Old environment variables are cleared
  • New environment is configured via /usr/local/greenplum-db/greenplum_path.sh
  • Correct binaries are referenced in PATH
# In your new gpadmin shell:
gpstart -a

# Verify Greenplum is running
psql -c 'select version()'
which postgres
postgres --version
postgres --gp-version
which psql
psql --version

Important Notes

  1. The Greenplum installation is intentionally preserved to enable fallback if needed
  2. The drop-in replacement process uses symbolic links to switch between Greenplum and SynxDB
  3. Start a new gpadmin shell after switching between versions to ensure proper environment setup
