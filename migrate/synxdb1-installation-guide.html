SynxDB 1: Installation Guide

Purpose

This guide provides step-by-step instructions for installing SynxDB 1 on Enterprise Linux 8 and 9 systems.

Security Considerations

SynxDB maintains high security standards through:

  • Cryptographically signed RPM packages
  • Signed repository metadata
  • GPG key verification
  • Package signature validation at multiple stages

All artifacts used in this process are cryptographically signed to ensure:

  • Package integrity
  • Origin authenticity
  • Protection against tampering
  • Secure dependency management

Package Verification

This guide includes steps to:

  • Import and verify the SynxDB GPG key
  • Verify package signatures before installation
  • Validate repository metadata
  • Confirm successful package installation

Repository Access

This guide assumes all cluster hosts have external access to Synx Data Labs repositories. For environments with restricted external access or to ensure consistent package availability, Synx Data Labs can provide a complete repository mirror for hosting within your environment.

Contact Synx Data Labs to obtain repository artifacts for internal hosting if:

  • Your cluster nodes don’t have external internet access
  • You prefer to host repositories within your infrastructure
  • You need to ensure package consistency across deployments

Introduction

SynxDB is a high-performance, enterprise-grade MPP (Massively Parallel Processing) database designed for large-scale analytics. It is a drop-in replacement for Greenplum 6, allowing seamless migration without requiring changes to existing workloads.

SynxDB is built for Enterprise Linux 8 (EL8) and 9 (EL9)-based distributions, including RHEL 8 & 9, Rocky Linux 8 & 9, Oracle Linux 8 & 9, and AlmaLinux 8 & 9. The installation follows a structured RPM-based approach, similar to EPEL, ensuring secure dependency management and updates.

All SynxDB artifacts are cryptographically signed, maintaining integrity and security throughout the installation process.

The process involves adding a signed yum repository entry and installing SynxDB using RPMs.

Installation Note

The -y option in the dnf install commands automatically confirms and proceeds with the installation. If you prefer manual confirmation, you can remove the -y flag.

Root Privileges Required

The following steps require root privileges. The commands in this guide assume you are logged in as the root user. If running as a non-root user, prepend sudo to each command.

Prerequisites

  • A supported EL9-compatible OS (RHEL 9, Rocky Linux 9, Oracle Linux 9, AlmaLinux 9) or EL8-compatible OS (RHEL 8, Rocky Linux 8, Oracle Linux 8, AlmaLinux 8)
  • Root privileges
  • dnf package manager
  • Internet access to retrieve repository and installation packages

Installation Steps

Security Considerations

All SynxDB artifacts are cryptographically signed to ensure their integrity and authenticity. Before proceeding with the installation, it is recommended to verify the GPG signature of the downloaded packages. This prevents potential tampering and ensures you are installing trusted software.

Step 1: Import SynxDB GPG Key

wget -nv https://synxdb-repo.s3.us-west-2.amazonaws.com/el9/stable/RPM-GPG-KEY-SynxDB
gpg --show-keys RPM-GPG-KEY-SynxDB
rpm --import RPM-GPG-KEY-SynxDB
rpm -q gpg-pubkey --qf "%{NAME}-%{VERSION}-%{RELEASE} %{SUMMARY}\n" | grep SynxDB

Step 2: Download and Install SynxDB Release RPM

For EL9:

wget -nv https://synxdb-repo.s3.us-west-2.amazonaws.com/el9/noarch/synxdb-release-1.0.0-rc2.el9.noarch.rpm

For EL8:

wget -nv https://synxdb-repo.s3.us-west-2.amazonaws.com/el8/noarch/synxdb-release-1.0.0-rc2.el8.noarch.rpm

Step 3: Verify the Package Signature

For EL9:

rpm --checksig synxdb-release-1.0.0-rc2.el9.noarch.rpm

For EL8:

rpm --checksig synxdb-release-1.0.0-rc2.el8.noarch.rpm

Step 4: Install SynxDB Repository Package

Important: Ensure that you install the correct SynxDB release package for your OS version. Installing an EL8 package on an EL9 system or vice versa will result in a failure.

For EL9:

dnf install -y synxdb-release-1.0.0-rc2.el9.noarch.rpm

For EL8:

dnf install -y synxdb-release-1.0.0-rc2.el8.noarch.rpm

Step 5: Verify Repository Registration

dnf repolist | grep SynxDB
rpm -qi synxdb-release

Step 6: Install SynxDB

dnf install -y synxdb

Step 7: Verify Installation

rpm -qi synxdb
ls -ld /usr/local/synxdb*

Step 8: Configure SynxDB Environment

Note: The following steps must be run as the gpadmin user, not as root.

su - gpadmin
source /usr/local/synxdb/synxdb_path.sh

Step 9: Verify Executables

Note: If running a multi-node SynxDB cluster, ensure these commands are executed across all nodes manually.

which postgres
postgres --version
postgres --gp-version
which psql
psql --version

Automating Multi-Node Deployment

To streamline the installation of SynxDB across multiple nodes, consider using automation tools. Here are some recommended approaches:

1. Using Ansible

Ansible allows you to automate installation across all nodes in the cluster using playbooks.

  • Create an Ansible inventory file listing all nodes.
  • Develop a playbook to:
    • Install the SynxDB repository package.
    • Install SynxDB using dnf.
    • Verify installation across all nodes.
  • Run the playbook to automate deployment.

2. Using a Bash Script with SSH

For environments without Ansible, a simple Bash script can help distribute installation tasks.

  • Define a list of nodes in a text file (e.g., hosts.txt).
  • Use a loop in the script to SSH into each node and run installation commands.

Example:

for host in $(cat hosts.txt); do
  ssh gpadmin@$host "sudo dnf install -y synxdb"
done

3. Using a Custom RPM Repository

If managing multiple clusters, setting up an internal repository can help centralize package management.

  • Mirror the SynxDB RPM repository internally.
  • Configure nodes to pull SynxDB packages from this repository instead of the public internet.

These approaches help ensure consistent installations across all nodes while reducing manual effort.

Conclusion

You have successfully installed SynxDB on your Enterprise Linux system. The database is now ready for initialization and configuration. Refer to the official SynxDB documentation for advanced setup and cluster configuration guidelines.
